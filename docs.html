Gitee 使用教程与协作规范

当前流程为：Gitee 主仓库 → GitHub 自动镜像 → Cloudflare Pages 部署。日常只向 Gitee 推送。

不要同时修改 GitHub 镜像仓库。镜像有延迟时，先确认 Gitee 提交记录。

首次配置

git clone git@gitee.com:tuilichaoshi/homepage.git
cd homepage
git remote -v

日常更新

git pull --rebase origin main
git add .
git commit -m "简短说明本次更新"
git push origin main

协作规范

  • 修改前先拉取最新代码。
  • 一个提交只解决一个主题。
  • 提交前检查密码、私钥、Token 和大文件。
  • 修改后检查链接、命令和手机端显示。

Slurm 常用命令教程

命令用途示例
sinfo查看分区和节点sinfo
squeue查看作业squeue -u $USER
sbatch提交脚本sbatch train.slurm
srun交互申请资源srun --pty bash
scancel取消作业scancel 作业ID
sacct查看历史资源sacct -j 作业ID

批处理脚本模板

#!/bin/bash
#SBATCH --job-name=demo
#SBATCH --output=logs/%x-%j.out
#SBATCH --time=01:00:00
#SBATCH --cpus-per-task=4
#SBATCH --mem=16G
set -euo pipefail
mkdir -p logs
python train.py
分区、GPU 参数、模块名称和内存上限以平台实际配置为准。

平台与数据规范

  • 私钥只保存在个人电脑，严禁上传仓库或聊天群。
  • 大型数据集、模型权重和运行输出不要提交到 Git。
  • 记录代码提交号、环境、关键参数和运行结果。
  • 定期清理缓存、临时文件和失败输出。
  • 退出交互式会话前确认进程已结束。
不要公开密码、私钥、动态验证码、访问 Token 和个人隐私信息。

开发协作约定

  • 技术名词和命令保持原样，说明适用环境。
  • 新增页面时同步更新主页导航。
  • 站点保持只读参考定位，不引入账号和评论。
  • 修改后在桌面和手机尺寸检查显示。
  • Cloudflare Pages 使用根目录 index.html，无需构建命令。

比赛推进与交付检查

  • 明确问题、用户和算力平台使用场景。
  • 完成最小可运行原型和端到端演示。
  • 记录环境、数据、作业脚本和运行结果。
  • 准备架构图、截图、演示视频和 README。
  • 在干净环境中复现关键流程。
